## FIRST RUN (vision prompt not changed after seeing the score)

Vision model: gemini-3.7-flash; prompt version(s): vision-prompt-1.

**Why this model.** Google's free tier allows 20 requests a day for each model (its own 429 message says so: `limit: 20`). `gemini-3.8-flash` ran out of quota after 20 bills, and `gemini-2.5-flash` is closed to new users, so the 10 labelled bills were read with one model that had quota, `gemini-3.7-flash`, and nothing else is mixed in: each model's readings are stored in their own folder (`data/cache/vision/<model>/`), and only this model's folder is scored. Readings by `gemini-3.8-flash` for other bills exist in their own folder and are not used here.

## Cost, speed and privacy, per reader

These are notes, not measurements, unless a figure is registered in `notes/numbers.md`. Provider terms, prices and free-tier limits change and were not checked from here: confirm them before relying on them.

| | Tesseract (local) | Vision model (Gemini, hosted) |
|---|---|---|
| Cost | Free software; runs on the machine that holds the bills | Pay per call on a paid tier; a free tier exists with request limits that make 40 bills take a few minutes (the fill script pauses between calls). Not priced here |
| Speed | A few seconds a page on a laptop (the intake card shows the time of a live read) | One network call per bill; mean 16.7 seconds on the 10 labelled bills |
| Privacy | The bill never leaves the machine | The bill image is sent to the provider. **A free tier may use inputs to improve the provider's products.** The case-pack bills are synthetic, so that is acceptable here; real vendor bills (GSTINs, bank and contract details) would need a paid, no-training tier, a data-processing agreement, or an in-house model |
| Failure | Misreads blurry photos; says so with a low confidence on most, but not all | May read confidently and wrongly, and its own confidence is only its estimate. Also fails to respond (limits, outages): the app does not wait for it, it uses the stored reading |
| In this build | Always on | Off by default; used only from the stored cache, no key and no network at run time |

## How it is used here

The vision model only extracts the same fields as JSON with a confidence for each; it never decides pass or fail. The cross-check is `app/reader/crosscheck.py`: where both readers agree the field is marked *two readers agree*; where they differ both values are shown side by side and the field is treated as not read until a person types it; neither reading is picked automatically. The app shows the stored vision reading and says so.
